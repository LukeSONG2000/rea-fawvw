# 车控最小开发版

更新日期为 2026-11-16。基线是一汽大众 iOS 444.28.0（518）。开发版使用 com.lukev.aftermarket，显示名为“一汽大众·车控”，与官方版并存。

## 用户确认的范围

保留原有登录和车辆身份体系，进入车控页面。登录接入优先级为账号密码、验证码、运营商一键授权、微信、苹果。账号密码已由用户在真机确认成功，其余方式尚未逐项验收。

用户要求去掉开屏广告、首次安装介绍与用户协议展示及勾选步骤。这些启动页面已实现跳过。后续用户已明确要求移除营销与冗余，并将多车切换入口放到车控页左上角车名。核心控制与状态查询入口继续保留。分类建议见 VEHICLE-FEATURES.md。

## 当前实现

CarControlOnly.dylib 通过主程序新增的 LC_LOAD_DYLIB 加载。原生 RootViewController 出现或应用回到前台后，选择包含 OneApp.CarController 的车辆页并隐藏底栏；内部保留原生控制器数组，避免破坏原有索引关系。该包装控制器在登录后承载 VWCarnet.CarSwitchViewController 与 MoscCarNetViewController。

存储的用户与令牌记录用于选择启动入口，账号有效性、令牌刷新、车辆授权及车控指令仍由原程序处理。未存储登录数据时请求原生 faw-vw://auth/login，登录完成后进入 faw-vw://carnet/carHome。密码方式优先，验证码切换保留。

广告和首次介绍页在加载后隐藏，并触发原有跳过按钮事件。独立协议弹窗隐藏并执行其原有授权继续回调，登录页隐藏协议说明及勾选行并复用原有确认事件。该实现包含自动继续本地协议确认的行为。

原程序启动时会拒绝独立 Bundle ID。经 LLDB 定位，开发版在原始文件偏移 0xe3f8 将启动身份检查的条件分支 40010036 改为 1f2003d5。签名脚本核对原指令后应用修改。

冷启动后曾卡在统计 SDK QTMobClick.getGlobalProperties 的同步等待，开发版将该 getter 改为返回空字典。此项处理仅替换这条统计属性读取。

## 安装与打包

本机开发证书和覆盖 iPhone Air 的描述文件用于签名。原厂推送、数字车钥匙、关联域与共享应用组等 entitlement 未包含在该开发描述文件中。

初期移除分享、Widget 和 Watch 扩展后，未同步清理原商店 SC_Info 安装元数据，导致覆盖更新报不存在的扩展 Info.plist，继而报 SINF 增量包错误。签名流程已清理重签副本中的 SC_Info。51 个薄 arm64 镜像的加密标记检查均为 cryptid=0。修复后同一 Bundle ID 覆盖安装已返回成功。

原始 IPA 与 recovered 提取物作为输入保留。签名副本在 output/signed/Payload/OneApp.app，当前签名包为 output/FAWVW-444.28.0-CarControlOnly-dev-signed.ipa，摘要与本机校验见 output/signed-build-report.json。

构建入口为 implementation/CarControlOnly/build.py，签名入口为 sign-development.py。重新签名会创建新的 signed 输出目录，脚本遇到现有目录会停止以避免覆盖现场。

## 验证与限制

- 原生密码登录由用户确认成功。
- 登录状态已备份并恢复，车辆页截图确认车辆状态与操作入口已加载，底栏不再提供首页、服务、商城和“我的”。
- 全新安装日志确认首次介绍跳过及独立协议回调执行，登录页截图确认协议说明与勾选行隐藏。
- codesign 深度严格校验与 IPA ZIP CRC 检查通过，同标识覆盖安装通过。
- 最终恢复登录后的冷启动日志确认进入 MoscCarNetViewController，广告跳过事件已执行，进程持续运行。
- 具体车辆控制指令尚未执行验证。车窗子选项、其他车型能力及其余登录方式尚待逐项核对。
- 最新候选版已加入营销入口隐藏和左上角车名切换入口；视觉验收与实际多车切换仍未完成。当前原生车辆列表可取得两条记录，但默认车辆操作尚未成功关联，不能标记多车切换可用。

应用数据备份仅保存在本机 output/device-backups。开发调试日志可能包含服务返回内容，不作为对外发布材料。

## 代理拦截修复

原生 AppSetting.isProxyAllow 已设置为 true，但用户截图证明业务层仍显示“禁止使用网络代理、抓包工具等”。因此，该开关不构成修复完成的证据。

进一步定位到 FV_NetworkService 的代理检查回调。候选版在原始文件偏移 0x18af8cc，将 CFNetworkCopySystemProxySettings 调用指令 a7a4a995 替换为 000080d2（mov x0, #0），进入现有的空配置分支。此项只修改这一处业务检查，不修改系统网络栈的代理路由或通用证书校验。签名脚本核对原始指令后应用补丁，当前签名候选包已复核该指令。

候选版已成功按 com.lukev.aftermarket 覆盖安装，codesign 深度严格校验通过。随后启动被 iOS 以 Locked 拒绝，故尚未验证代理开启时能否进入车控及加载数据。需要解锁真机并打开名称为“一汽大众·车控”的开发版；官方版没有此补丁。

2026-11-16 后续真机验证：开发版成功启动，日志显示网络路径仍包含 utun5 与 proxy，用户回复“可以”，确认当前代理环境可使用。此次验证没有发送实际车控指令，也不代表所有代理或 HTTPS 解密配置均已验证。

同次真机截图已显示高尔夫 A8 GTI 车控页、续航和八个核心操作入口，未显示代理拦截页。截图保存在 output/proxy-car-screen.png。多车切换与营销清理仍按前述待验收状态记录。
