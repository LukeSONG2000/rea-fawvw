# 车控 App：拟物遥控器与分级信息

更新：2026-11-17。目标安装保持 `com.lukev.minimalclient`，名称“车控”，覆盖已有独立客户端，保留会话和默认车偏好。原生二开宿主与真正官方 App 不作为本次 UI 安装目标。

## 首页与车辆选择

- 左上角按车型名称打开原生下拉菜单；显示年款、VIN 尾 6 位、当前单选标记和默认启动标记。同一组最多一辆车处于选中状态。
- “将当前车辆设为默认”显式保存默认车；下次启动优先选择该车。普通临时切车不更改默认车。初次无默认值时优先 GTI，已保存车辆不存在时重新选可用车辆。
- 右上角进入当前车辆的信息目录。
- 首页为实体遥控器造型：收窄机身、金属包边、磨砂颗粒、挂绳槽、凹入玻璃 LCD、七段数字、带边沿和投影的胶质按键。
- LCD 显示续航、燃油百分比、四门/四窗摘要、总里程、真实车况采集时间。读取成功不等于车端刚刚更新；始终显示采集时间。
- 按键直接显示中文用途与图标。中央银色锁车键、上方解锁键，周围是车窗、闪灯、鸣笛和发动机。多个操作的按键显示“更多 ⌄”。按当前车已开通能力增减控制项。

## 信息层级

一级目录保留 8 个入口，不堆叠全部字段：

| 一级入口 | 二级内容 |
|---|---|
| 车况与能耗 | 车况概览；全部车况信号（再按能耗、门锁、车窗、保养分组） |
| 门窗与安全 | 车身状态；防盗通知；速度提醒设置/记录；围栏设置/通知 |
| 行程记录 | 短期、长期、周期；按时间倒序；点单条查看全部返回字段 |
| 保养与健康 | 保养周期与机油；健康提醒 |
| 空调与充电 | 空调/行前空调/辅热状态；出发计划；空调定时；充电状态 |
| 位置与寻车 | 位置接入状态；鸣笛闪灯配置 |
| 车辆档案 | 车型/年款/发动机/变速箱/车漆；完整档案与设备字段 |
| 服务与设备 | 已开通能力、权限、用户、配对、发动机记录/最近结果 |

数据按需查询当前车辆，不在打开目录时跑全量调查或查询另一辆车。字典/列表继续进入下级页面，原始 XML 通过保留属性、层级和叶子文本的解析器展示；信号元数据进一步进入详情。燃油与机油明确区分，缺失为“未提供”，不支持为不可用状态；未知枚举标注含义待确认，未经确认的容量不解释为剩余燃油升数。行程时长用小时/分钟，保养负值显示“已超出”，平均油耗单位尚未独立取证，显示数值而不伪造单位。

## 触觉与指令

- 按键按下：轻触反馈与物理压下效果。
- 切车、设默认、导航、菜单选择：选择反馈。
- 已确认成功/失败：对应通知反馈；无法确认含义的回执不伪报成功。
- 发动机启动提供必填 SPIN；门锁、解锁、车窗提供安全码输入。密码键盘，字段隐藏，仅本次使用，不落盘、不写日志，用完清空输入框和适配层临时属性。
- 指令执行期间禁止重复点击和切车；车辆切换、状态刷新及指令回调绑定车辆和请求序号，过期回调丢弃。超时不宣称车辆操作成功。
- UI 验收只导航和查询，不发送物理车控。触觉实际感受和物理指令逐项成功仍需人工真机验收。

## 构建与验收

常规包：`python3 implementation/MinimalClient/build.py --ipa`。仍仅包含 6 个 SDK 依赖，无原 App 资讯、商城等页面及资源。

只读 UI 验收：`python3 implementation/MinimalClient/build.py --ui-review` 后，用环境变量 `MC_UI_REVIEW=1` 启动。测试文件仅在此参数下参与编译，导航真实信息页并在私密沙盒 `Documents/ui-review` 写图与脱敏统计。常规交付包不包含自动导航脚本。人工中途返回时停止后续导航，避免越界。早期截图确认材质层曾遮挡 UIButton 内容，已改为独立前景文字/图标层；最终须重新检查实机显示。

本地截图/日志只放 Git 忽略的 `output/private-gti-location/` 与 `output/*.log`，不向公共文档复制 VIN、位置或鉴权数据。

## 当前功能边界

- UI 保留现有导入身份会话的自动登录能力；全新账号的独立密码/验证码登录及长期令牌刷新尚未实现，不将会话恢复宣称为完整登录闭环。
- GTI 原生 MOSC `getLastGnss` 已证实可取坐标，但独立客户端尚未接入其认证、签名与绑定流程。位置页如实显示尚未接入，不复用旧坐标或把 MBB CF 失败解释为整车不能定位。详细证据见 `GTI-INFORMATION-AND-LOCATION.md`。
- “已开通能力”不等于所有指令已实车验证。按钮沿用已有控制适配器；本轮只做查询和 UI 验收。
